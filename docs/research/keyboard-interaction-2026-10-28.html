Ceteris Keys

A keyboard grammar for the workbench: one command registry, a standard keymap with Paradox conventions, an opt-in vim mode whose cursor lives in place, time and branch, a command palette that also takes terminal mnemonics and plain English, a query language for selections and edits, hint labels for anything on screen, and automation that stays reproducible.

Principles



  
One command registryEvery action is a named command with typed arguments. Menus, buttons, the palette, both keymaps and the ex line call the same commands. Where a command has a CLI form (ADR 0113), the ex form is that subcommand, so the console history is already a scenario script.

  
Keys never write stateA key produces a command. Commands that change the world append to the edit log (14.2) or issue an order (0145). Keymaps, hints and the palette are presentation: they enter no run hash, and a test asserts that rebinding changes no state hash, as 0140 does for chrome.

  
The cursor has three coordinatesPlace (cell, province, state, country), tick (monthly, daily while a war runs) and branch. Every motion moves one of them. Marks and the jump list store all three, so "go back" means back in space, time and history at once.

  
Two keymaps, one grammarStandard is the default and contains only conventions people already know, from Excel, VS Code, the three desktop platforms, Paradox and Factorio. Vim is opt-in and modal. Both are text files; mods may ship keymaps, which never touch state.

  
Teach through the paletteEach palette row shows its key in the active keymap and its ex form. A which-key panel opens after any prefix. Lessons (0158) teach keys at the moment the mechanic first appears.

  
Pause when typingEntering the command line, a value prompt or hint mode pauses the clock (on by default) and the prompt shows the tick the edit will land on. An edit's tick is the view tick at commit, never wall-clock, so typing speed cannot change a run.

Operators: edits as verbs


An operator plus a target makes one edit in the log, at the view tick. If you are looking at the past, the edit lands in the past and the branch replays from the nearest snapshot (14.3). God-mode operators refuse unless :set god is on; in seat play only in-world edits are possible, and the refusal names the in-world alternative.

Macros, repeat and global commands


qa … q records keys into "a; @a replays, @@ repeats, 20@a twenty times. Macros are presentation: only the edits they produce enter the log, so a recorded macro never makes a run non-reproducible. Saved macros are text, so :let @a = '...' in ceterisrc works.


There are two ways to apply something to every place that matches a predicate, and the difference matters for replay:

:g/coastal/normal 3<C-a>Whatever the keys produce at each match, like vim's :gFixed sets.

Where sources disagree


    

  • Digits. Paradox wins: 1–5 set speed. Control groups move to Ctrl/Alt + digit and map modes to Shift + digit.
    • 

  • Arrows. Excel wins: arrows move the cursor, because the cursor is what keyboard edits act on. Panning stays on WASD and the mouse, where grand strategy and Factorio players already have it.
    • 

  • F-keys. VS Code and the debugger win over Paradox panel keys (F1 country, F2 economy and so on). Panels move to Ctrl Shift + letter. Time on F5/F9/F10 is the stronger mapping: running a simulation is closer to debugging than to any game panel.
    • 

  • F11. Full screen, as on Windows and Linux. "Step into" has no use, because F10 already steps a day during a war.
    • 

  • F12. Explain, as in "go to definition", rather than Steam's screenshot key. Postcards (0144) go in the palette and can be bound to Steam's key if the player wants.
    • 

  • Alt. On Windows, holding Alt also shows menu access keys. The two coexist: a tap toggles map numbers and Alt plus a letter opens a menu.
    •

Command palette


Ctrl Shift P or F1 in the standard keymap, as in VS Code; Ctrl-k or : in vim mode. One fuzzy list over the registry and the world. Ctrl P opens it filtered to places, dates and branches.






    

  • Commands with their key in the active keymap and their ex form, ranked by frecency.
    • 

  • Places: provinces, states, countries, markets, chokepoints, in English and local names (0143).
    • 

  • Times: typing 2008-09 offers "go to" and "fork at".
    • 

  • Branches, marks, saved queries, situations, goods, series.
    • 

  • Queries: input that starts with where previews the matching set live on the map, then offers select, edit, peer set or save.
    • 







    

  • Arguments as chips: bisect asks for a predicate, then lanes; Tab moves between chips.
    • 

  • Seat wording: titles follow the regime register of 0140, and the canonical name always matches too, so "cabinet", "central committee" and "government" find the same panel.
    • 

  • Context: commands that need a selection or a war are listed last and greyed, with the reason, not hidden.
    • 

  • Teaching: run a command from the palette three times and the row starts showing "Next time: cis".

Query language


One small language for search, visual selection, :where, :g, peer sets and saved queries. Its text form is what an edit by query stores (0155), so it must be deterministic: no wall-clock, no randomness, and every column it names has a unit that the parser checks.


query   := term (('&' | '|') term)*
term    := '!' term | '(' query ')' | atom
atom    := flag                         coastal  port  capital  edited  rationed(steel)
         | column cmp number unit?      gdp_pc < 12k   tariff(wheat) >= 10%   pop > 1M
         | key '=' name                 country=Spain   state="Castilla y León"   union=EU
         | near(place, k)               near(Madrid, 2)        within 300km of Lisboa
         | rank(column) cmp k           rank(gdp_pc) <= 10   (within the current set)
         | pct(column, peers) cmp n     pct(debt_gdp, income-group) > 90
         | routes(through, edge)        routes(through, Suez)
time    := query '@' date | query 'over' date '..' date     deficit(food) > 0 over 2007..2008


Examples: /Sev finds by name. /port & deficit(food) > 0 highlights matches. :where rationed(steel) & country=DEU tfp +1 is an edit by query. :peers pct(reserves_months, currency=peg) < 25 is a peer set.

Terminal style


The Bloomberg Terminal is the best keyboard interface for people who live inside numbers, and its grammar fits Ceteris closely: load a subject, then run a function on it. It needs no new mode. The palette and the ex line already accept it, and a "Terminal" workspace (a tab page) arranges four linked panels the way a terminal user expects.






Subject, function, go


Type a subject, an optional type key, a mnemonic, then Enter (the terminal's GO): Spain WEI, Sevilla DES, wheat GP. With no subject, the function runs on the cursor. In the terminal keymap the F-keys become subject types, as Bloomberg's yellow keys are: F2 country, F3 state, F4 province, F5 market, F6 good, F7 branch, F8 formation. That settles ambiguous names such as Georgia or Córdoba without a menu.


Every list prints numbered rows, and typing a number then Enter opens that row, so WEI then 2 Enter opens Portugal. Esc is the terminal's MENU key and walks back through the jump list.


Linked panels


Each panel carries a link colour. Panels in the same group change subject together, so a GP chart, a DES page and a market table follow the map cursor while a second group stays pinned to a peer for side-by-side reading. Linking is presentation only.


Monitors


A monitor is a saved table of subjects with live columns, the WEI or MOST pattern: rows from a query, columns from series with a window (0155), sparklines, sorting by any column, and conditional colours from the semantic tokens. Monitors update each tick and are the natural home for peer sets.

Rule edits are the one new mechanism here. A rule fires per target, the first time the target matches from the rule's tick onward (the default "once" policy), and each firing is logged as an ordinary edit with its own tick, so blame, bisect and g; treat firings like hand-made edits. In seat play a rule may only use the seat's own levers, which makes it a standing policy close to the commitments of 0162. God-mode rules carry the god flag like any god edit. The demo implements :when with the "once" policy.



Natural-language input


Typing a sentence into the palette or the ex line works with AI off. A small controlled-English grammar ships with the app and compiles common forms ("raise tariffs by 4 in coastal Portuguese provinces from 2008", "when GDP falls below 17 in Spanish provinces, raise productivity by 1", "which provinces have GDP below 16") into the same edit and query text a user could type. The demo's palette runs that grammar. Anything the grammar cannot read goes, if the user has turned it on, to the intervention compiler of ADR 0125.






The rules


    

  • Compile, preview, commit. The sentence becomes ex text, shown with the matched set lit on the map, the tick it will land on, and whether it is in-world or god mode. Enter commits it, Tab edits the compiled text first.
    • 

  • The log stores the compiled text. The sentence is kept as a comment, and for model output so are the model id and a prompt hash, for audit. Replays read only the compiled lines and never call a model.
    • 

  • Ask, never guess. Ambiguous places, goods or dates come back as numbered choices ("Georgia: 1) the country 2) the US state").
    • 

  • Nothing outside 14.2. A sentence that maps to no edit type is refused with the nearest edit types listed.
    •

Fitting the other surfaces






Branch verbs (0116)


:bisect loads its probes into the quickfix list as they finish; ]q steps through them and the map shows each probe's subset. The answer lands on the edit log line, highlighted. :blame fills the same list ranked by channel-shutdown effect, and Enter on an entry jumps to the edit's place and tick. :rebase onto main reports skipped edits in the list instead of a dialog. Cherry-pick is yank and put across branches: "ayy in one edit log, "ap in another.


Economic lenses (0155)


gmb turns on the bottleneck lens; Ctrl-] on a rationed cell walks the shortfall one link upstream and Ctrl-t walks back. t then a label opens the route inspector; x on an edge forks a branch with it closed. Peer sets are saved queries (:peers). Tap Alt or :set nu for map numbers. Headroom crossings are ]a targets.


Seat chrome (0140)


Keys never change with the seat. The focus ring and the cursor use the seat accent; edits stay proof magenta and forks violet. Panel titles change by regime register; the palette matches both the register title and the canonical name.






War surfaces (0145-0166)


Orders are typed objects with a mission verb and an objective (0147), which maps onto an operator grammar. Select formations with gf hints or v, then:




o verb targetoa attack, od defend, oh hold, os screen, oe encircle, ol delay; target by motion, text object or hint. oafsk: attack the province labelled sk.


v path ofDraw a front or phase line by walking the cursor in visual mode, then assign it.


]u [uNext formation with no order, or whose order went stale after HQ latency.

:planOpen the battle planner with the selection as the force.




Time motions use the daily clock while a war runs, so ) is one day. An order issued by keys and the same order from a planner produce the same state (0147 test).







Building it on winit and Slint (ADR 0088)






    

  • One input router ahead of Slint. winit KeyEvent goes to a keymap engine (mode state machine, pending-key trie, counts, registers) that emits registry commands. Slint gets a key only when a Slint text field has focus; even then Esc and Ctrl-[ go to the engine.
    • 

  • Logical and physical keys. Vim and most bindings match logical_key (the character), so { and $ work on any layout. Camera panning matches physical_key. Dead keys and IME composition pass through untouched in insert and command-line modes.
    • 

  • Timeouts. timeoutlen (default 700 ms) for ambiguous prefixes; the which-key panel opens after 400 ms.
    • 

  • Keymap files. TOML per keymap plus ceterisrc for ex commands, in the config folder; never in a pack or a run.
    •

  • Tests. Every registry command is reachable from the palette. No two bindings collide within a context. Replaying a recorded key log on a fixture produces the same edit log, and the same state hash, on every platform. Changing keymap or entering hint mode changes no state hash.
    • 

  • Accessibility. Slint's AccessKit tree names every hint target, so the keyboard path is also the screen-reader path. All labels and the which-key panel follow the reduced-motion setting.
    • 

  • Phasing. Registry, palette, standard keymap and hints with the P3 workbench; vim mode once the edit log and branch manager exist, since it is mostly a grammar over them; war bindings with the W2-W5 surfaces.

Open questions


Leader key (decided). Space stays pause in both keymaps and the vim leader is Ctrl Space (ADR 0188). On macOS, Ctrl Space switches input source by default; the first launch in vim mode says so and offers to rebind.


Does c commit at once or open a draft? Recommended: commit on Enter, since u is free and the edit is only a log entry. The standard keymap keeps the explicit draft panel with Apply and Fork-then-apply.


Edits while the clock runs. Recommended: autopause on any prompt, on by default. With autopause off, the prompt freezes the view tick it shows, and the edit lands there.


Word motions. w as "next state in the last direction" is a guess. The alternative is w walking the current ranked list (search hits, query results). Worth a quick playtest in the demo above.
